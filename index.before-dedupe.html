1부 · 기획 의도와 시장

기획 의도

“내가 그린 그림이 살아 움직이고, 내가 직접 조종할 수 있다면?”

  • 누구나 캐릭터를 그릴 수 있지만, 그것을 3D로 만들고 움직이게 하려면 모델링·리깅·게임 개발 지식이 필요하다
  • 3D 생성 AI는 많지만, 결과물이 “움직이고 노는 경험”까지 이어지지 않는다

초기 MVP

이미지를 넣으면 3D 캐릭터로 바뀌고, 바로 가지고 논다

이미지 → 3D 캐릭터 → 내 몸으로 조종 → 게임

추후 확장

같은 3D 결과물을 다른 곳에 연결한다

  • 3D 프린팅: 내 캐릭터를 실물 피규어로
  • 레이싱 게임: 내가 그린 차로 레이스 참가
발표에서 가장 중요한 슬라이드. 기술보다 “왜 만드는가”를 먼저 말한다. 아이가 그린 그림을 가족이 함께 움직여 보는 장면을 예로 든다. 초기 MVP는 “이미지 → 3D → 놀기”까지다. 3D 프린팅과 레이싱 게임은 같은 3D 결과물을 연결하는 추후 확장이며, 지금 되는 기능처럼 말하지 않는다. 자세한 확장 방향은 마지막 장(확장 비전)에서 다시 보여준다.

시장 현황

직접 만들고 3D로 즐기는 시장은 커지고 있다

  • 크리에이터 경제: 2027년 약 4,800억 달러
  • 3D 애니메이션: 2030년 510억 달러

하지만 3D를 “만드는 서비스”와 “노는 서비스”는 아직 따로 있다

인접 시장 전망 · 출처: Goldman Sachs, Grand View Research

수치는 인접 시장의 성장성을 보여주는 자료일 뿐, 우리 서비스의 시장 규모나 예상 매출이 아니다. 두 수치를 더하지 않는다. 질문이 나오면 추가로: 3D 매핑·모델링 시장 2030년 167.8억 달러 전망 (Grand View Research). 출처: Goldman Sachs — https://www.goldmansachs.com/insights/articles/the-creator-economy-could-approach-half-a-trillion-dollars-by-2027 Grand View Research (3D 애니메이션, 510.3억 달러) — https://www.grandviewresearch.com/industry-analysis/3d-animation-market Grand View Research (3D 매핑·모델링) — https://www.grandviewresearch.com/industry-analysis/3d-mapping-3d-modeling-market

타깃 사용자 분석 (가설)

주 타깃: 가족 (아이 + 부모)

  • 상황: 아이가 그린 그림을 함께 가지고 놀고 싶다
  • 불편: 그림은 종이에 남고, 디지털로 살리려면 전문 도구가 필요
  • 니즈: 설치·학습 없이 브라우저에서 바로, 몸으로 함께 노는 경험

보조 타깃: 친구 그룹

  • 상황: 각자 만든 캐릭터로 대결하고 싶다
  • 불편: 기존 게임 캐릭터는 정해져 있어 “내 것”이 아니다
  • 니즈: 각자 PC에서 접속해 내 캐릭터로 온라인 대결
페르소나는 가설이다. 인터뷰·설문을 아직 진행하지 않았음을 그대로 말한다. 가상의 응답자를 만들지 않는다.

Draw2World AI의 O는 목표 기준이다 (만들기: 규칙 기반 경로 구현 완료, 놀기: 개별 저장소에서 실험 완료, 통합은 개발 예정). 상세 가격 (2026-10-15 공식 페이지 기준): Meshy 무료 월 100크레딧 + 유료 구독 / Tripo 무료 월 200크레딧, Pro 월 ₩29,700 (연간 결제) / Just Dance 게임 별도 구매, Just Dance+ 월 ₩5,900. 출처: Animated Drawings — https://github.com/facebookresearch/AnimatedDrawings Meshy — https://www.meshy.ai/pricing/ Tripo — https://www.tripo3d.ai/ko/pricing Just Dance — https://www.ubisoft.com/ko-kr/game/just-dance/plus

1부 · 기획 의도와 시장

차별점과 경쟁력

  • 생성에서 끝나지 않는다: 그림 → 캐릭터 → 관절 → 조종 → 게임까지 한 흐름
  • 설치 없이 브라우저에서: 게임과 MediaPipe 추론은 브라우저에서 실행
  • 개인정보: 웹캠 영상은 내 PC에서만 처리, 게임에는 동작 결과만 사용
  • 무료 지향: 오픈소스 모델과 로컬/자체 GPU 추론, 유료 API 의존 없음
  • GPU 없이도 동작하는 대체 경로: 고성능 GPU가 없는 PC에서도 캐릭터를 만들 수 있다
2D → 3D 방법어떻게 만드나필요한 것상태
① 생성 AI 경로학습된 AI 모델이 보이지 않는 면까지 추론GPU 서버 / GPU PC개발 중
② 대체 경로 (규칙 기반)그림 외곽선(실루엣)에 두께를 계산해 입체로 만듦 — AI 모델 없이 기하 계산브라우저만구현 완료
경쟁 비교에서 도출한 차별점. 속도·품질은 아직 측정 전이므로 차별점으로 주장하지 않는다. 대체 경로 설명: 2D를 3D로 만드는 방법이 두 가지다. 생성 AI 경로는 품질 잠재력이 높지만 GPU가 필요하고 느리다(CharacterGen 2D 단계 1회 39분 51초 기록). 규칙 기반 경로는 형태가 단순하지만 브라우저에서 바로 돌아가서, 일반 가정 PC나 GPU 서버·인터넷이 없는 발표장에서도 동작한다. 주의: 대체 경로가 생성 AI보다 품질이 좋다고 말하지 않는다. “기본 동작을 보장하는 경로”로 소개한다.

2부 · 서비스 기획

서비스 흐름

사용자 흐름 (목표)

  1. 그림을 그리거나 업로드
  2. 캐릭터 분할 → 3D 형태 생성
  3. 관절 추정 → 스키닝
  4. 웹캠으로 손·몸 동작 인식 (MediaPipe)
  5. 내 캐릭터로 게임 플레이
흐름 전체가 하나로 통합된 상태는 아니다. 각 단계가 개별 저장소에서 구현·실험되었고, 통합이 다음 단계라는 점을 분명히 말한다.

3부 · 진행 방식과 이번 주 결과

진행 방식: 데모 먼저, 오픈소스는 그다음

처음 방식

오픈소스를 먼저 찾고, 할 수 있는 걸로 제품을 만든다

→ 제품이 오픈소스의 한계에 끌려간다

바꾼 방식

데모를 먼저 만들고, 필요한 오픈소스를 찾아 개선한다

→ 데모에서 막히는 지점이 곧 개선 포인트

프로세스: 데모 기획 → OSS 탐색 → 베이스라인 측정 (시간·비용) → 병목 식별 → 개선 → 재측정

“오픈소스에 맞춰 제품을 만들지 않고,
제품에 필요한 오픈소스를 골라 개선한다”

이번 주에 팀원들이 각자 데모를 만들며 7개 저장소에서 실험했다. 그 과정에서 막힌 지점(리깅 변형, 관절 오추정, 손동작 흔들림)이 다음 슬라이드의 개선 포인트가 되었다.

막힌 지점 = 개선 포인트

문제시도한 해결현재 상태

손동작 대상 흔들림, 양손 충돌최근 대상 유지, 랜드마크 필터, 손별 소유권개선율 미측정

AI 역량(모델 선택·후처리·검증)과 OSS 역량(탐색·통합·직접 개선)이 드러나는 슬라이드. 실패도 그대로 보여준다.

서로 다른 실험의 수치를 합치거나 팀 공통 성능으로 말하지 않는다. 과거 기록(80→90%, 11ms 등)은 측정 로그 확인 전까지 사용하지 않는다.

추후 계획

지금까지

바이브 코딩으로 빠르게 데모를 만들며
가능성과 막히는 지점을 확인했다

앞으로

핵심 오픈소스를 개선·최적화하기 위해
먼저 설계하고, 설계대로 구현한다

  1. 설계: 대표 파이프라인(그림 → 3D → 리깅 → MediaPipe → 게임) 아키텍처와 기준 저장소 확정
  2. 핵심 오픈소스 선정: 2D→3D, 리깅, 동작 인식 후보를 같은 입력으로 비교 (시간·품질·라이선스)
  3. 베이스라인 측정: 그림 크기·GPU·모델 버전 고정, 처리 시간 10회 이상, 조명 3종 인식 테스트
  4. 개선·최적화: 측정에서 드러난 병목부터 — 리깅 변형, 관절 오추정, 손동작 흔들림
  5. 구현·통합: 설계에 맞춰 하나의 서비스로 연결하고 Before / After로 재측정
지금까지는 바이브 코딩으로 여러 데모를 빠르게 만들어 가능성과 한계를 확인하는 단계였다. 그 결과 7개 저장소가 각자 따로 존재한다. 다음부터는 방식이 바뀐다. 핵심 오픈소스를 골라 개선하고 최적화하려면 측정 기준과 구조가 먼저 있어야 하므로, 설계를 먼저 하고 설계대로 구현한다. 리스크 대응: GPU 서버·인터넷이 없는 발표장을 위해 규칙 기반 브라우저 경로를 백업 데모로 유지한다. 로컬 LLM 캐릭터 꾸미기는 코어가 안정된 뒤 진행한다. 이어서 확장 비전으로 마무리.

모두 향후 목표 · 관련 실험은 별도 저장소에서 진행되었으며, 핵심 서비스와 아직 연결되지 않음

MVP는 “그림 → 캐릭터 → 몸으로 조종”이다. 이 핵심이 안정되면, 같은 2D→3D 엔진을 실물(3D 프린팅), 다른 게임 장르(레이싱, 오픈월드)로 넓힐 수 있다. 이번 주 다른 저장소에서 이미 관련 실험을 해 본 경험이 있다는 점을 근거로 든다. 단, 지금 바로 되는 기능처럼 말하지 않는다. 3D 프린팅: AI로 만든 캐릭터 메시는 구멍·두께 문제로 바로 출력이 안 될 수 있어 출력용 검사·보정이 필요하다. local-ai-cad의 STL 출력은 CAD 형상 기준 실험이다. 레이싱: f1 저장소의 레이싱은 Draw2World 핵심 기능과 별개의 선행 실험이다. 그 저장소의 성능 수치는 인용하지 않는다.
